## ⚡ Changed

**Tempo and key are measured by neural networks.** essentia is gone. Tempo now comes from [TempoCNN](https://github.com/hendriks73/tempo-cnn) (Hendrik Schreiber), sharpened to a hundredth against the track's onsets; key comes from [S-KEY](https://github.com/deezer/skey) (Deezer, ICASSP 2025). Both run inside the plugin in plain JavaScript, with no WebAssembly and nothing downloaded, so they work the same on desktop and on a phone, offline. They are ports, not lookalikes: on real tracks they give the originals' answers — tempo to the thousandth, key probabilities within 0.0003 — and the tests hold them to that. The major version marks this: the same file can now read differently than it did.

**Tempo to a tenth.** A tempo used to be snapped to the nearest whole number within 0.35, to hide essentia's drift. The new detector lands within 0.01 of a straight beat, so anything further off is real: a beat VirtualDJ reads as 89.31 now shows 89.3 instead of 89. Straight beats still show whole. ×2 and ÷2 on the badge keep the tenth.

**The badge says how sure the key is** — "key 73% sure", and the next guess when the network was torn between the two modes of one tonic. Tracks measured by an older version keep their profile votes until they are measured again.

**`main.js` is a fifth smaller** (2.99 → 2.44 MB): the networks' weights take less room than essentia did.

## 🎧 Added

**The measure button takes up older measurements.** Tracks measured by essentia count as not yet measured: the gauge button under the playlist header includes them and measures them anew, one at a time. Their old tempo and key stay on show until the new ones arrive. Hand corrections are never touched.

**You can see which track is being measured.** Its playlist row lights up in the accent colour with a spinning loader where the tempo goes, the list scrolls to it as the batch moves on (once per track, so browsing the list during a batch is not fought), and the progress notice names the file.

## 🛟 Fixed

- Moving the tempo window no longer rounds a measured tempo to a whole number: it re-folds from the detector's own value, so 89.3 → 178.6 → 89.3 comes back exactly.

## 🧹 Under the hood

Tempo and key run side by side in two workers, so a track takes as long as the slower of the two. The weights are converted from the original models by `tools/export-models.py`; `tests/detect.test.mjs` pins the originals' answers on synthetic audio.
