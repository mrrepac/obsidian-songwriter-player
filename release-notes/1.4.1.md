A bug-fix release for 1.4.0.

## 🐞 Fixed

**Playback speed and transposition survive a restart.** They are meant to be remembered per track — a beat you are learning stays slow, a song stays in the key you sing it in — and they were being saved correctly, but thrown away again the next time Obsidian started. If you set a speed or a key in 1.4.0 and found it back at the recording the following day, this was why. Values are restored within the range the player can set (0.5–2×, ±12 semitones), and a track whose only setting is a speed or a key is no longer discarded as empty.

**"Open track's note" no longer loses its way.** Clicking an audio file in the file explorer used to drop the link back to the note the track was picked up from — even when it changed nothing about what was playing. The note now travels with the track as it loads, so `Alt+D` keeps working after a look at the file list, in manual mode, and after accepting an offered switch.

**The playlist stays where you left it.** Every track change rebuilt the whole list, which reset its scroll to the top — so on a folder of any size, ⏭ sent the view back to the first file while the track that was actually playing sat somewhere off screen. The list is now rebuilt only when the playlist itself changes; stepping through it moves the highlight and scrolls the playing track into view.

**Listened time is counted by the clock.** An hour of practice at 0.5× counted as half an hour, and "count a play after 5 seconds" waited for 10. Both now measure real seconds regardless of playback speed.

**Inline players resolve their file against the right note.** In a split, a background tab or a hover preview, an embedded track was looked up as if it were linked from whatever note happened to be in focus — which could find a same-named file in a different folder.

## 🔧 Under the hood

- The observer that catches embedded players sees every DOM change in the app, including each keystroke in the editor; its cleanup sweep now runs at most once per frame.
- `package.json` declared MIT while the project moved to AGPL-3.0 in 1.4.0, and its version had been left at 1.2.0. Both now match the rest of the repository.
- CI builds and type-checks every push and pull request, instead of finding out at release time.
