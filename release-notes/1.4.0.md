## ⚠️ The licence changed: MIT → GNU AGPL-3.0

This release measures tempo and key with [essentia.js](https://github.com/MTG/essentia.js) (Music Technology Group, Universitat Pompeu Fabra), which is AGPL-3.0 — so the plugin as a whole now is too. Using it carries no obligations; distributing a modified build means keeping the source open under the same licence. `main.js` grows from 0.1 MB to 2.7 MB because the analysis library is compiled into it — Obsidian installs exactly three files, so it cannot ship alongside.

## ✨ New

**Tempo and key, measured.** A badge next to the track name shows `140 · F#m`. Measured once per file, in a worker — the analysis takes a few seconds and never blocks typing or playback — then remembered.

- **Two independent tempo estimators cross-check each other**, and the number comes from the one that proved more accurate on real tracks. Verified against tracks whose tempo was known: 160, 122 and 131 all came out exactly right, including one where a single estimator would have rounded to 162.
- **The preferred range folds the octave** — a beat heard at 160 or at 80 is a matter of feel, so the result lands in 80–159 by default (adjustable; the range is exactly one octave, so every tempo maps to a single value). `×2` and `÷2` in the badge menu override it per track.
- **Five key profiles vote**, from both the classical and the EDM-oriented families. When they split — which happens on the mode, not the tonic — the badge says so, offers both, and plays the tonic triad of either so it can be settled by ear. Your correction is final: analysis never overwrites it.

**Play slower or faster with the key intact.** The badge in the transport row shows the tempo it is actually playing at — 105 instead of 140 — rather than an abstract factor. `Alt+-` / `Alt+=` step by one bpm, `Alt+0` returns to the recording. Kept per track: a beat you are learning stays slow until you speed it up.

**Transpose without touching the tempo** (desktop). `Alt+PageUp` / `Alt+PageDown` move by a semitone, and the menu lists the target keys, so it reads "+2 — Abm" rather than "+2". The shifter is inserted between the player and the speakers only when a shift is actually asked for, so an untransposed track plays exactly as it did before.

**Save what you hear as a file.** Once the key fits, the badge menu writes a copy next to the original — `beat-tone+2bpm140.wav` — with the transposition and the speed baked in. It is an ordinary file: it plays with the marker, the A-B zone, the waveform and the playlist, drags into a note, and opens in a DAW.

## 🔍 On the sound

The shifter is granular with phase-aligned grains, tuned against measurements rather than by ear alone: grains are stitched with a crossfade (overlap-add would ripple the level once alignment moves a grain), resampled with a cubic interpolator, and the aligner prefers the smallest move among equally good ones. Against the first working version this cut spectral distortion by ~2.5 dB, raised level fidelity from 0.90 to 0.95, and halved the delay to ~36 ms. A 1024-sample grain measured better than 2048 and 4096 — a longer window holds sustained notes better but smears drums, which is the wrong trade for beats.

Pitch accuracy is within ~0.5 cents of the requested note, and the tempo does not move: checked on synthetic tones, on rendered files decoded back from disk, and on audio captured live from the player's own output.
